# PR Compass — Product Definition

## Target user

A software engineer reviewing a pull request in an unfamiliar part of the codebase.
They have access to the diff but lack the context needed to evaluate it quickly.

## Problem

Code review requires significant background knowledge:
- Which behavior actually changes (not just which lines)?
- Which other files are affected but not in the diff?
- What assumptions did the author make?

Reviewers currently acquire this context through searching, reading, and asking questions.
That takes time and is easy to skip under deadline pressure.

## Solution

A compact review brief — generated by Bob analyzing the PR — that answers the three key questions
and links every claim to a source location.

## MVP scope

**In scope:**
- Bob skill that analyzes a PR and produces structured JSON.
- Website that renders that JSON as a single-page review brief.
- Demo fixture for initial display.
- Sample project (search service + client) to serve as the PR subject.

**Non-goals (not in scope for MVP):**
- Authentication or user accounts.
- GitHub OAuth or live PR fetching.
- Database or persistent storage.
- Chatbot or conversational interface.
- Automatic approval, merge, or repair of PRs.
- Vector database or custom agent framework.
- Production deployment infrastructure.
- Support for arbitrary repository uploads.

## Acceptance criteria

1. The website loads `public/demo/review-brief.json` and renders all four sections without errors.
2. Loading a malformed JSON file shows a clear error message.
3. All unit tests pass.
4. TypeScript compilation produces no errors.
5. The production build succeeds.
6. Every rendered claim that has source evidence shows a file reference.
7. The demo banner is visible and clearly labeled for mock data.
8. Missing values (URL, commit SHA) are shown honestly — never manufactured.

## Measurement goal

Reduce active reviewer effort without degrading understanding or causing important issues to be missed.

**Proposed proxy metric:** time from "PR opened" to "reviewer posts first substantive comment."

A later evaluation (using `evidence/evaluation.md`) will compare:
- Reviews with PR Compass brief vs. reviews without.
- Active lookup time, accuracy of understanding, and missed issues.
